## 问题 1 · Accuracy、Precision、Recall、F1 分别是什么意思？

**提问时间**：看到分类指标输出时

**原话**：

> `Accuracy=0.900 Precision=0.000 Recall=0.000 F1=0.000`
>
> 这几个概念对应中文怎么理解？

### 回答

用内容审核场景来理解。先规定：

```text
正类 = 色情或违规内容
负类 = 正常内容
```

假设一共有 100 条内容：

```text
10 条违规
90 条正常
```

模型把 100 条全部预测为正常，于是得到：

```text
Accuracy=0.900
Precision=0.000
Recall=0.000
F1=0.000
```

### Accuracy：准确率

Accuracy 也可以理解成总体正确率。它回答：

> 所有内容中，模型一共判断对了多少？

公式：

```text
Accuracy = 判断正确的数量 / 全部数量
```

这个模型正确判断了 90 条正常内容：

```text
Accuracy = 90 / 100 = 0.9
```

所以准确率是 90%。

但是，它没有找到任何违规内容。这说明正负样本数量差异很大时，只看 Accuracy 会产生误导。

### Precision：精确率、查准率

Precision 回答：

> 模型判定为违规的内容中，有多少真的违规？

公式：

```text
Precision = 真正违规且被拦截的数量 / 模型拦截的总数量
```

例如，模型拦截了 20 条内容，其中 15 条真的违规：

```text
Precision = 15 / 20 = 0.75
```

Precision 越高，误杀越少。

当前例子中，模型一条内容都没有拦截，分母是 0。这个值在数学上无法计算；配套代码按常见实现将它记为 `0`，表示模型没有正确识别出任何正类。

可以把 Precision 记成：

> 拦下来的内容，准不准？

### Recall：召回率、查全率

Recall 回答：

> 所有真正违规的内容中，模型找到了多少？

公式：

```text
Recall = 被模型找到的违规数量 / 实际违规总数量
```

这个例子中有 10 条违规内容，模型一条都没找到：

```text
Recall = 0 / 10 = 0
```

Recall 越高，漏放越少。

可以把 Recall 记成：

> 真正违规的内容，找全了吗？

### F1：Precision 和 Recall 的综合分数

F1 同时考虑 Precision 和 Recall：

```text
F1 = 2 × Precision × Recall / (Precision + Recall)
```

只有 Precision 和 Recall 都比较高，F1 才会高。

当前例子中：

```text
Precision = 0
Recall = 0
F1 = 0
```

### 最简单的记法

| 指标 | 中文 | 审核场景中的问题 |
|---|---|---|
| Accuracy | 准确率 | 全部内容中，总共判断对了多少？ |
| Precision | 精确率、查准率 | 拦下来的内容中，多少真的违规？ |
| Recall | 召回率、查全率 | 真正违规的内容中，找到了多少？ |
| F1 | F1 综合分数 | 拦得准和找得全，是否兼顾？ |

一句话记忆：

```text
Accuracy：总体对不对
Precision：抓到的是不是真的
Recall：真的有没有都抓到
F1：Precision 和 Recall 是否兼顾
```

## 问题 2 · 过拟合是什么？

**提问时间**：学习 train、validation、test 时

**原话**：

> 过拟合是什么？

### 回答

过拟合可以理解成：

> 模型太熟悉训练数据，连训练数据中的偶然细节和噪声都记住了，但遇到没见过的数据时表现不好。

英文是 `overfitting`。

### 用做题来理解

假设考试前拿到 100 道练习题。

一个学生没有理解解题方法，只是把这 100 道题的答案背了下来：

```text
练习题正确率：100%
新题正确率：60%
```

他在做过的题上表现很好，但换一批题就不会了。这就是过拟合。

模型也会出现同样的问题：

```text
train 表现很好
validation / test 表现明显更差
```

### 内容审核中的例子

假设训练数据中的大部分违规文本都包含“免费资源”这几个字。

模型可能没有真正学会什么是违规内容，而是记住了：

```text
出现“免费资源” → 预测为违规
```

在训练集上，这条规则可能非常准。但遇到新数据时会出问题：

```text
“这里有免费的学习资源”       → 被误判为违规
“私密视频点击这个链接领取”   → 因为没有“免费资源”而被漏掉
```

模型记住了训练数据里的表面特征，没有学到能够推广到新数据的规律。

### 怎么看出过拟合

训练时同时观察 train 和 validation：

| 训练过程 | train | validation | 判断 |
|---|---|---|---|
| 两边一起变好 | 变好 | 变好 | 模型正在学习有效规律 |
| train 继续变好，validation 不再变好 | 变好 | 持平 | 可能开始过拟合 |
| train 继续变好，validation 反而变差 | 变好 | 变差 | 明显过拟合 |

典型走势是：

```text
训练前期：train F1 上升，validation F1 也上升
训练后期：train F1 继续上升，validation F1 开始下降
```

所以不能只看训练集指标。训练集本来就是模型反复学习的数据，在上面表现好并不意外。

### validation 和 test 为什么有用

三份数据各有不同职责：

```text
train：用来更新参数
validation：用来观察模型对新数据的表现，并选择训练方案
test：最后验收，只看一次
```

模型没有使用 validation 和 test 更新参数，因此它们更能反映模型是否学到了可以推广的规律。

### 常见处理办法

刚开始学习时，先记住四种即可：

1. 增加更多、更有代表性的训练数据。
2. 不要把模型设计得过于复杂。
3. validation 不再变好时停止训练，这叫 early stopping。
4. 使用正则化，让模型不要过度依赖少数特征。

当前阶段最重要的不是记住所有解决方案，而是养成一个习惯：

> 训练时同时看 train 和 validation，最终结果看 test，不能只报告 train 指标。

### 最简单的判断

```text
train 好，validation 也好
→ 模型可能真的学会了

train 很好，validation 明显差
→ 模型可能只是记住了训练数据
```

## 问题 3 · F1 是什么平均数？为什么它能反映 Precision 和 Recall 的平衡？

**提问时间**：学习 F1 指标时

**原话**：

> `F1 = 2 × Precision × Recall / (Precision + Recall)`
>
> 这个是什么平均数吗，为什么 F1 更可靠？有什么数学直觉吗？

### 回答

F1 是一种平均数，更准确地说是 Precision 和 Recall 的**调和平均数**。

它也可以写成：

```text
F1 = 2 / (1 / Precision + 1 / Recall)
```

### 为什么不是普通平均数

普通的算术平均数是：

```text
(Precision + Recall) / 2
```

而 F1 使用调和平均数。两者的区别在于，调和平均数会更明显地受到较小值影响。

假设：

```text
Precision = 1.0
Recall = 0.5
```

算术平均数是：

```text
(1.0 + 0.5) / 2 = 0.75
```

F1 是：

```text
2 × 1.0 × 0.5 / (1.0 + 0.5) = 0.667
```

F1 更低，是因为这个模型虽然拦得很准，但只找到了全部违规内容的一半。Recall 明显不足，不能让 Precision 的高分把它掩盖掉。

### 数学直觉：短板会拉低 F1

看几组例子：

| Precision | Recall | 算术平均 | F1 |
|---:|---:|---:|---:|
| 1.0 | 1.0 | 1.000 | 1.000 |
| 0.8 | 0.8 | 0.800 | 0.800 |
| 1.0 | 0.5 | 0.750 | 0.667 |
| 1.0 | 0.1 | 0.550 | 0.182 |
| 1.0 | 0.0 | 0.500 | 0.000 |

最后一行最容易理解：

```text
Precision = 1.0
Recall = 0.0
```

意思是：模型拦下来的内容全都正确，但一个真正违规的内容都没有找到。

如果用算术平均数，分数还有 `0.5`，看起来不算太差。F1 是 `0`，因为 Recall 是 `0`，模型没有完成“找出违规内容”这个任务。

从公式看，F1 的分子包含：

```text
Precision × Recall
```

只要其中一个接近 `0`，乘积就会接近 `0`，F1 也会被拉低。这就是它的数学直觉：两个指标都高，F1 才会高。

### 放到内容审核里

假设：

```text
Precision = 0.95
Recall = 0.40
```

说明模型拦下来的内容大部分确实违规，但只找到了 40% 的违规内容，还有 60% 漏掉了。

算术平均数是：

```text
(0.95 + 0.40) / 2 = 0.675
```

F1 约为：

```text
2 × 0.95 × 0.40 / (0.95 + 0.40) ≈ 0.563
```

F1 会更明确地提醒你：这个模型虽然拦得准，但漏得太多。

### “F1 更可靠”要有前提

更准确的说法是：

> 当你既关心 Precision，又关心 Recall，并且希望用一个数字衡量两者的平衡时，F1 通常比单独看 Accuracy 更合适。

F1 不是所有业务场景下都绝对更可靠：

```text
更怕误杀正常内容 → 更关注 Precision
更怕漏掉违规内容 → 更关注 Recall
两者都重要       → 可以看 F1
```

如果漏放违规内容的代价远高于误杀正常内容，就不能只看 F1，还应该重点看 Recall。必要时可以使用让 Recall 权重更高的 Fβ。

### 一句话记忆

```text
算术平均：两个分数的普通平均
F1：更重视短板的平均
```

F1 高，说明 Precision 和 Recall 通常都不会太差。

## 问题 4 · sigmoid 函数是什么？

**提问时间**：学习 Logistic Regression 的 logit 和概率时

**原话**：

> sigmoid 函数是什么？

### 回答

sigmoid 是一个函数。它把任意大小的数字压缩到 `0` 和 `1` 之间：

```text
任意大小的 logit
        ↓ sigmoid
0～1 之间的数字
```

公式是：

```text
sigmoid(z) = 1 / (1 + exp(-z))
```

这里的 `z` 就是模型输出的 logit，`exp` 是指数函数。

### 看几个具体数字

| logit `z` | sigmoid(z) | 直观理解 |
|---:|---:|---|
| `-2` | 约 `0.12` | 更像负类 |
| `0` | `0.50` | 两边各一半 |
| `2` | 约 `0.88` | 更像正类 |
| `5` | 约 `0.99` | 非常像正类 |
| `-5` | 约 `0.01` | 非常像负类 |

所以 Logistic Regression 的流程是：

```text
Linear 计算 logit
→ sigmoid 把 logit 转成 0～1 的概率
→ threshold 把概率转成 0 或 1
```

例如：

```text
logit = 2
sigmoid(2) ≈ 0.88
```

如果 threshold 是 `0.5`：

```text
0.88 >= 0.5
→ 预测为正类 1
```

如果模型输出：

```text
logit = -2
sigmoid(-2) ≈ 0.12
```

那么：

```text
0.12 < 0.5
→ 预测为负类 0
```

### 为什么不能直接把 logit 当概率

因为 logit 没有固定范围：

```text
logit 可能是 -10、0、3、100
```

但概率必须在 `0` 和 `1` 之间。sigmoid 负责完成这个范围转换。

它还有一个方便的性质：

```text
logit > 0  ↔  sigmoid(logit) > 0.5
logit = 0  ↔  sigmoid(logit) = 0.5
logit < 0  ↔  sigmoid(logit) < 0.5
```

因此，threshold 为 `0.5` 时，也可以直接看 logit 的正负来判断类别。

### sigmoid 是不是现实世界中绝对准确的概率

不一定。

例如模型输出 `0.8`，通常可以理解成“模型认为它属于正类的程度较高”，但不代表现实中一定有 80% 的概率是正类。模型是否校准良好，还需要单独评估。

在当前学习阶段，先记住它的主要作用：

> sigmoid 把模型的原始分数转换成 0～1 之间的概率，方便我们使用 threshold 做二分类。
