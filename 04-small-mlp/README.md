# 04 MLP：从一层模型走到多层模型

这一章不要一上来就背 MLP、隐藏层、ReLU。先回答一个问题：

> 03 里的 Logistic Regression 已经能做分类了，为什么还需要多一层？

这一章按下面的顺序学习：

```text
一个输入
→ 一个隐藏单元
→ 多个隐藏单元
→ 一层隐藏层
→ MNIST 的 784 → 128 → 10
```

## 你从前面带来了什么

只需要记得 03 的这几件事：

```text
x：输入数据
y：正确答案
模型：根据 x 计算预测
loss：预测和 y 的差距
训练：算 loss → backward → 更新参数
```

在 03 中，输入是两个特征，模型大致在算：

```text
logit = w1*x1 + w2*x2 + b
```

它把一个输入直接变成一个分数，再经过 sigmoid 得到二分类概率。

## 先补四个词

### 1. 输入、标签和预测

假设要判断一条数据是不是正类：

```text
x = 这条数据的输入
y = 这条数据的正确答案
ŷ = 模型根据 x 算出来的答案
```

在本页的小例子里：

```text
x1、x2：两个条件，0 表示不满足，1 表示满足
y：是否恰好满足其中一个条件
```

在 MNIST 里：

```text
x：一张 28×28 的图片，也就是 784 个像素值
y：图片代表的数字，例如 7
```

### 2. 一个隐藏单元是什么

一个隐藏单元就是一个小计算器：

```text
z = w1*x1 + w2*x2 + b
```

它做三件事：每个输入乘上自己的权重，把结果加起来，再加上偏置。

这里最容易写错的是乘法对象。它是：

```text
权重 × 输入
```

不是：

```text
w1 × w2
```

`w1`、`w2`、`b` 是模型要学习的参数。h1 和 h2 是两个不同的隐藏单元，所以它们有各自的参数。

### 3. 什么叫隐藏

它叫“隐藏”，只是因为这个结果不是最终答案，而是模型中间算出来的一个数：

```text
输入 x
→ 隐藏单元算出的中间结果
→ 输出层
→ 最终预测
```

为了方便学习，我们暂时把 h1 叫作“至少一个条件满足”，把 h2 叫作“两个条件都满足”。真正训练模型时，这些权重和中间结果由数据和 loss 逐渐学出来。

### 4. ReLU 是什么

ReLU 是中间结果后面的一个简单函数：

```text
ReLU(z) = max(0, z)
```

它只有两条规则：

```text
z < 0：输出 0
z >= 0：原样输出 z
```

例如：

```text
ReLU(-0.5) = 0
ReLU(0.5) = 0.5
```

先把 ReLU 当成一个开关就够了。它不是另一个隐藏单元，也不是训练算法。

## 为什么不能只用 03 的一层模型

我们用一个很小的分类问题观察差别。目标是：只有一个条件满足时，输出 `1`；两个都满足或都不满足时，输出 `0`。

```text
(1, 0) → 1    只有一个条件满足
(0, 1) → 1    只有一个条件满足
(0, 0) → 0    一个条件都没满足
(1, 1) → 0    两个条件都满足
```

### 先看 Logistic Regression 为什么会为难

03 的 Logistic Regression 只有一个加权求和：

```text
logit = w1*x1 + w2*x2 + b
```

如果要让 `(1, 0)` 变成正类，那么 `x1` 对分数的贡献要比较大。如果要让 `(0, 1)` 变成正类，那么 `x2` 对分数的贡献也要比较大。

可是到了 `(1, 1)`，两个贡献会同时出现，分数反而更容易变大。单层模型很难做到“分别满足一个时分数高，两个同时满足时分数又低”。

这不是它算得不够快，而是它只有一个加权求和，缺少中间判断。

### 再看 MLP 怎样拆开

MLP 先用不同的隐藏单元做中间判断，再把中间判断组合起来：

```text
h1：识别“至少一个条件满足”
h2：识别“两个条件都满足”
输出层：根据 h1 和 h2 判断“是否恰好一个”
```

在页面使用的这组参数下，四种输入会产生下面的中间结果：

| x1 | x2 | 正确答案 y | h1：至少一个 | h2：两个都满足 | 最终判断 |
|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 0 | 0 |
| 1 | 0 | 1 | 0.5 | 0 | 1 |
| 0 | 1 | 1 | 0.5 | 0 | 1 |
| 1 | 1 | 0 | 1.5 | 0.5 | 0 |

你可以这样读最后两列：

```text
h1 有输出，h2 没输出 → 只有一个条件满足 → 判为 1
h1 有输出，h2 也有输出 → 两个条件都满足 → 判为 0
h1、h2 都没输出 → 一个条件都没满足 → 判为 0
```

所以隐藏层的作用是增加中间步骤。它不是凭空多出来的一层，而是让模型可以先回答几个小问题，再组合成最终答案。

## 打开交互式讲义

打开 [mlp-lab.html](./mlp-lab.html)。请按这个顺序看，不要先看 MNIST 代码。

### 第一步：先看输入和任务

页面开始的任务是：`x1`、`x2` 两个条件中，是否恰好满足一个。

```text
(1, 0) 和 (0, 1) 应该判为 1
(0, 0) 和 (1, 1) 应该判为 0
```

### 第二步：只看 h1

先暂时忘记 `z1`、`h1` 这些名字。页面里的 `x1`、`x2` 只有 0 和 1 两种状态，可以把它们当成两个开关。

我们先数一数有几个开关打开：

```text
x1 + x2
```

h1 想回答的是“至少有一个开关打开吗？”。所以它使用：

```text
z1 = x1 + x2 - 0.5
h1 = ReLU(z1)
```

这里的 `-0.5` 是一个门槛：

```text
一个都没开：0 - 0.5 = -0.5 → ReLU 后是 0
开了一个：  1 - 0.5 =  0.5 → ReLU 后是 0.5
开了两个：  2 - 0.5 =  1.5 → ReLU 后是 1.5
```

所以 h1 的含义是：只要至少有一个条件满足，它就会有正数输出。

`z1` 只是 ReLU 之前的原始值，`h1` 是 ReLU 之后的值。拖动 `x1`，观察这两个值的变化，先不用管输出层。

### 第三步：再看 h2

现在需要另一个小计算器回答：“两个开关都打开了吗？”它使用的门槛更高：

```text
z2 = x1 + x2 - 1.5
h2 = ReLU(z2)
```

同样把三种情况算一遍：

```text
一个都没开：0 - 1.5 = -1.5 → ReLU 后是 0
开了一个：  1 - 1.5 = -0.5 → ReLU 后是 0
开了两个：  2 - 1.5 =  0.5 → ReLU 后是 0.5
```

所以 h2 只有在两个条件都满足时才有正数输出。

### 第四步：再看输出层

现在 h1、h2 已经分别告诉我们两个中间结果：

```text
h1 有输出：至少一个条件满足
h2 有输出：两个条件都满足
```

我们的目标是“恰好一个”。因此：

```text
h1 有、h2 没有 → 正类
h1 有、h2 也有 → 负类
h1 没有、h2 也没有 → 负类
```

输出层把这两个信号组合成一个分数。这里的参数不是唯一答案，我们只选择一组容易算的数字：

```text
logit = 2.0*h1 - 6.0*h2 - 0.5
```

这些数字可以这样选出来：

```text
先设一个负类起点：-0.5

只有一个条件满足时：h1=0.5，h2=0
希望 logit 变成正数，所以给 h1 一个权重 2：
2×0.5 - 0.5 = 0.5

两个条件都满足时：h1=1.5，h2=0.5
此时 h1 会带来 2×1.5=3
所以给 h2 一个权重 -6，让它带来 -6×0.5=-3：
3 - 3 - 0.5 = -0.5
```

以四种输入为例：

```text
(0, 0)：h1=0，h2=0，logit=-0.5 → 负类
(1, 0)：h1=0.5，h2=0，logit=0.5 → 正类
(0, 1)：h1=0.5，h2=0，logit=0.5 → 正类
(1, 1)：h1=1.5，h2=0.5，logit=-0.5 → 负类
```

最后才使用 sigmoid：

```text
logit → sigmoid → 0 到 1 之间的概率
```

注意：`2`、`6`、`0.5` 只是这组玩具数据的一组可行参数，不是神经网络固定的数字。真实训练时，输出层的参数也会从数据和 loss 中学习出来。

## 从小例子到 MNIST

小例子是：

```text
2 个输入 → 2 个隐藏单元 → 1 个二分类输出
```

MNIST 的代码是：

```python
nn.Sequential(
    nn.Flatten(),
    nn.Linear(28 * 28, 128),
    nn.ReLU(),
    nn.Linear(128, 10),
)
```

逐行对照：

```text
Flatten：把 28×28 图片摊平成 784 个数字
Linear(784, 128)：用 128 个隐藏单元处理 784 个输入
ReLU：把这 128 个中间结果分别过一遍 ReLU
Linear(128, 10)：把 128 个中间结果组合成 10 个数字分数
```

`Linear(784, 128)` 里面有 128 个隐藏单元。每个单元都会使用 784 个像素和自己的一组权重：

```text
一个单元：w1*x1 + w2*x2 + ... + w784*x784 + b
```

`Linear(128, 10)` 再把 128 个中间结果组合成 10 个分数，分别对应数字 `0` 到 `9`。

二分类通常输出一个分数，MNIST 输出 10 个分数，然后选择分数最高的数字。当前只需要知道这个区别，不必马上深入 `CrossEntropyLoss` 的公式。

## 训练过程其实没有换

你在 02、03 里学过的训练循环仍然成立：

```text
一批图片和正确数字
→ MLP 算出 10 个分数
→ loss 比较分数和正确数字
→ loss.backward() 算出所有参数的梯度
→ optimizer.step() 更新参数
```

变化只有两个：参数变多了，中间多了一层计算和 ReLU。训练仍然是同一个循环。

## 最后再看 batch、epoch 和 learning rate

先把网络前向计算看懂，再看训练参数：

```python
BATCH_SIZE = 64
EPOCHS = 8
LEARNING_RATE = 0.1
```

```text
batch：一次拿多少张图片计算 loss 和更新参数
epoch：完整看完训练集一次
learning rate：每次更新参数时走多远
```

一个 epoch 里会有很多个 batch。每处理一个 batch，模型更新一次参数。

自己的图片不需要提前处理。服务会自动转成灰度图，识别白底黑字并反色，裁剪数字，再缩放和居中到 28×28。

### 为什么内置测试图片也可能预测错

`prediction-demo/test_images` 中包含数字 0～9 各一张，它们来自训练时没有参与参数更新的 MNIST test 数据。

当前 checkpoint 在这十张图片中识别正确 9 张，数字 `5` 被误判成 `6`。这个错误应该保留：`test_acc=0.900` 表示在测试集上大约 90% 正确，不表示每一张图片都会正确。

## 学完检查

1. 在小例子里，输入 `x1`、`x2` 和标签 `y` 分别是什么？
2. 一个隐藏单元具体计算哪条公式？
3. “隐藏”为什么不表示它很神秘？
4. ReLU 对负数和正数分别做什么？
5. `Linear(784, 128)` 中的 `128` 表示什么？
6. MLP 和 03 的 Logistic Regression 相比，增加了什么？
7. MLP 的训练循环和 02、03 相比有没有改变？
8. 训练完成后，模型保存在哪里？
9. 模型输出的十个 logit 怎样变成十个概率？

参考答案：

1. `x1`、`x2` 是两个输入条件，`y` 是是否恰好满足一个条件。
2. `w1*x1 + w2*x2 + b`，每个隐藏单元都有自己的一组权重和偏置。
3. 它只是中间结果，不是最终预测，所以叫隐藏。
4. 负数变成 `0`，正数保持不变。
5. 隐藏层里有 128 个隐藏单元。
6. 增加了隐藏单元、隐藏层和 ReLU，让模型可以先做中间判断，再组合成更复杂的结果。
7. 没有改变，仍然是预测、算 loss、`backward()`、`optimizer.step()`。
8. 保存在 `04-small-mlp/prediction-demo/mnist_mlp.pt`，里面是模型结构对应的参数值和训练元数据。
9. 使用 softmax。十个概率之和为 1，概率最大的位置就是预测的数字。
