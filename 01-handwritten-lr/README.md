# 手写线性回归：从零开始的讲义

## 这份讲义假设你会什么

只要你会：

- 加减乘除、平方
- 看到 `y = 2x + 1`，知道它是一条直线

就够了。

**不需要**会求导，**不需要**知道什么叫"梯度"，**不需要**学过微积分。
这些讲义里都从零讲起。

---

## 第 0 章 · 我们要做什么

给一堆点，找一条直线，让它尽量穿过这些点。

比如你手上有这样的数据：

```
x   1    2    3    4     5
y   2    5    8   10    14
```

一眼能看出来，y 大概是 x 的 2 倍多一点。但**具体是多少？**

而且真实世界的数据不会这么整齐，会带噪声：

```
x   1.2   1.5   1.9   2.3   2.6
y   2.1   4.9   3.8   5.4   6.1     ← 有高有低，没那么听话
```

我们要做的是：**让计算机自己从数据里找出这条直线的公式。**

---

## 第 1 章 · 一条直线，由两个数决定

直线的公式长这样：

```
y = w · x + b
```

- **w** 叫「斜率」：x 每多 1，y 多多少
- **b** 叫「截距」：x = 0 时 y 是多少

这两个数，就是我们要找的**参数**。

> 「训练模型」听起来很高级，其实就是「找出这两个数」。

一开始我们什么都不知道，就先随便猜：w = 0，b = 0。

---

## 第 2 章 · 怎么知道猜得好不好

对每一个点，算一下：

```
预测 − 真实 = 误差
```

误差有正有负。如果直接把所有误差加起来，正负会互相抵消 —— 比如 +5 和 −5 加起来是 0，看起来"完美"，其实错得离谱。

所以要先**平方**（平方之后一定是正数），再把所有点的加起来，最后**取平均**。

这个数叫 **loss**（损失）。

```
loss 越小 = 猜得越好
loss = 0  = 完美
```

记住一件事：**给一组 (w, b)，就能算出一个 loss。**

所以 loss 是 w 和 b 的函数 —— 你喂给它两个数，它吐给你一个数。

---

## 第 3 章 · 天真办法，和它的死穴

要找让 loss 最小的那组 (w, b)，最直接的想法是：**试**。

死穴是：w 和 b 都是连续的数，能取无穷多个值。**试不完。**

换个思路：

> 先随便猜一个。然后问一句 ——
> **「我把 w 稍微改一点点，loss 会变大还是变小？」**
>
> 变小，就往那个方向改。

就这一句。整个梯度下降就是这句话。

---

## 第 4 章 · 先手动挪一下试试

先用最简单的情况：**一个点** `(x=2, y=6)`，模型是 `y = w·x`（先不管 b）。
真相是 w = 3，但我们假装不知道。

猜 w = 1.0：

```
loss(1.0) = (1×2 − 6)² = 16
```

现在手动往两边各挪一点点：

```
w = 0.95    loss = (1.9 − 6)² = 16.81     ← 变大了
w = 1.00    loss =              16.00     ← 现在在这
w = 1.05    loss = (2.1 − 6)² = 15.21     ← 变小了
```

往右挪 loss 变小。**所以 w 应该变大。**

好，但是这个方法太笨了 —— 每走一步都得算三次。

真正的问题是：**能不能不算，直接就知道"往右挪，loss 会怎么变"？**

能。这个东西叫**斜率**。

---

## 第 5 章 · 斜率：只用初中代数就能算出来

我们要回答的是：

> w 从 1.0 挪到 1.0 + δ（δ 是个很小的数），loss 会变成多少？

把式子展开就行：

```
loss(1 + δ) = ( (1+δ)×2 − 6 )²
            = ( 2 + 2δ − 6 )²
            = ( 2δ − 4 )²
            = 4δ² − 16δ + 16
```

盯着最后一行看：

| 项 | 是什么 |
|---|---|
| `16` | 原来的 loss |
| `−16δ` | 跟着 δ 走的主要部分 |
| `4δ²` | δ 的平方。δ 很小时，它小到可以忽略 |

所以当 δ 很小的时候：

```
loss(1 + δ) ≈ 16 − 16δ
```

这句话的意思是：**w 每往右挪 1，loss 大约减少 16。**

这个 **−16**，就是 loss 对 w 的**斜率**。

它一次性告诉了你两件事：

- **符号 = 方向。** 这里是负数 → 往右挪 loss 会降 → 那就该往右挪。
- **大小 = 力度。** 每挪 1，loss 降 16。这个数越大，越值得挪。

> 「斜率」在数学书里也叫**导数**。是同一个东西的两个名字。
> 别被"导数"这个词吓到 —— 它说的就是"挪一点点，结果变多少"。

---

## 第 6 章 · 写成公式

刚才是一个具体的例子。现在换成一般的公式。

对任意的 w，任意一个点 `(x, y)`：

```
loss(w + δ) = ( (w+δ)·x − y )²
```

先把当前的误差记作 `e = w·x − y`，代进去：

```
            = ( e + δ·x )²
            = e²  +  2ex·δ  +  x²δ²
              ↑        ↑         ↑
           原来的   主要项    δ很小，可忽略
            loss
```

所以主要项里，δ 前面的那个系数就是斜率：

### 斜率 = 2·e·x = 2 × (预测 − 真实) × x

把这三个部分翻译成人话：

| 部分 | 含义 |
|---|---|
| `预测 − 真实` | 错在哪、错多少。**这是方向的来源** |
| `× x` | 这个错里，w 该负多大责任。x 越大，w 越该负责 |
| `× 2` | 常数，不重要 |

**那如果有 25 个点呢？**

每个点各算一个斜率，然后**取平均**。

因为 25 个点各自都想要一个不同的 w，没人能满足所有人，就取一个"让整体最不难受"的折中。

---

## 第 7 章 · 挪多远？—— 学习率

斜率告诉了你**方向**，但没说**挪多远**。

```
w = w − 学习率 × 斜率
```

学习率（lr）是**你自己定**的一个数：

| lr | 结果 |
|---|---|
| 太小 | 每次挪一丁点，走得像蜗牛 |
| 合适 | 又快又稳地到 |
| 太大 | 崩 |

**为什么太大就崩？** 回到第 5 章那个被忽略的 `4δ²`。

δ 很小的时候它确实可以忽略。但 δ 一大 —— 而 δ 有多大，正是 lr 决定的 —— 它就不能忽略了。

用真实数字看，在 w = 1.0 处：

```
  δ     用近似公式算     真实 loss
0.05       15.20         15.21
0.80        3.20          5.76      ← 已经差挺多了
1.50       −8.00          1.00      ← 完全是胡说，loss 不可能是负的
```

两个规律：

1. **步子越大，误差越大**，而且是按 δ 的**平方**增长 —— 步子加倍，误差四倍。
2. **近似值永远比真实值乐观**（预测的 loss 总是比真实的小）。因为 loss 是向上弯的曲线，那条切线永远躺在曲线下方。

再大一点，你会落到比出发点还高的地方。**那不叫下降，那叫发散。**

> 所以学习率的本质是：**你愿意相信「斜率」这个近似多远。**

---

## 第 8 章 · 两个参数：梯度登场

现在把 b 加回来：`y = w·x + b`。两个参数都要调。

方法和刚才一模一样，**各算各的斜率**：

```
w 的斜率 = 2 × 平均( (预测 − 真实) × x )
b 的斜率 = 2 × 平均(  预测 − 真实      )
```

**为什么 b 那里没有 `× x`？**

因为 b 是整体上下平移，跟 x 没关系。
而 w 管的是"倾斜程度" —— x 越大，w 动一点点对预测的影响就越大，所以 w 该为这个错负更多责任。

这两个数打包在一起，就叫 ——

### 梯度 = ( w 的斜率, b 的斜率 )

就这么多。**「梯度」不是什么高深的东西，它只是「每个参数各自的斜率」打包成的一组数。**

- 参数只有 1 个 → 梯度就是 1 个数（其实就是斜率）
- 参数有 2 个 → 梯度就是 2 个数
- 参数有 100 万个 → 梯度就是 100 万个数

原理完全一样，一点没变。

---

## 第 9 章 · 串起来：这就是梯度下降

```
重复很多很多次：
    1. 用当前的 w, b 算预测
    2. 算 loss
    3. 算梯度 —— 每个参数各自的斜率     ← 每轮都要重算！
    4. w 和 b 各自减去：学习率 × 自己的斜率
```

注意第 3 步**每轮都重算**。这不是为了省事写成循环，而是因为
**位置一变，斜率就变了**。这是整个方法能跑通的关键。

就这些。

**「梯度下降」这个名字，说的就是「沿着斜率往下的方向，一小步一小步地走」。**

至于为什么求个斜率就知道往哪走 —— 因为斜率本来就是"往这个方向挪，结果会变多少"的定义。它管的就是这件事。

## 附录 · 之后去看 PyTorch

等你把上面的都弄明白了，再去看 PyTorch，会发现 `loss.backward()` 一点魔法都没有：

```python
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

y_pred = w * x + b
loss = ((y_pred - y) ** 2).mean()
loss.backward()               # ← 这一步 = 我们自己手算的斜率
with torch.no_grad():
    w -= lr * w.grad          # ← 这一步和我们写的完全一样
    b -= lr * b.grad
    w.grad.zero_()            # ← 别忘记清零
```

`backward()` 做的事，就是我们手推的那两个公式。

它只是**自动**帮你算斜率而已。**没有任何魔法。**
