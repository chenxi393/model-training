# 用 PyTorch 重写线性回归

## 这份讲义假设你会什么

假设你已经读完 **[01-handwritten-lr](../01-handwritten-lr/README.md)**，并且清楚这 4 行在干什么：

```
用当前的 w, b 算预测 → 算 loss → 算梯度 → w 和 b 各自减去 学习率 × 自己的梯度
```

**不需要**你会用 PyTorch。这个单元从 `torch.tensor` 讲起。

---

## 第 0 章 · 这一单元要做什么

算法一点没变。还是线性回归，还是梯度下降，还是那 4 步。

变的只有一件事：**梯度不再由我们手推了。**

第 1 单元里，我们自己算出 `w 的斜率 = 2×平均(误差×x)`，写死在代码里。
这次我们把这件事交给 PyTorch，然后**拆开看它替我们做了什么**。

沿着这条路走：

```
Tensor  →  nn.Module  →  loss.backward()  →  optimizer.step()
```

每一站都对应第 1 单元里的某样东西。走到最后你会发现：
**PyTorch 没有做任何我们没做过的事。它只是把那些事自动化了。**

> 这就是这个单元的目标。不是学新算法 —— 是搞明白"自动"两个字背后到底是什么。

---

## 第 1 章 · Tensor：会记账的数组

Tensor 就是数组。跟第 1 单元里那些数、那些列表，没本质区别：

```python
a = torch.tensor([1.0, 2.0, 3.0])
```

但它比数组多带了一本**账本**。

```python
>>> a.requires_grad
False
>>> a.grad_fn
None
```

默认是关着的。现在打开它：

```python
>>> w = torch.tensor(0.0, requires_grad=True)
>>> w.requires_grad
True
```

`requires_grad=True` 的意思是：

> **"这个数是我要调的。请把它怎么被算出来的，记下来。"**

### 记的是什么

记的**不是数值，是做法**。看：

```python
>>> pred = w * x
>>> pred.grad_fn
<MulBackward0>              ← 这一步做的是"乘法"

>>> e = pred - y
>>> e.grad_fn
<SubBackward0>              ← 这一步做的是"减法"

>>> loss = e ** 2
>>> loss.grad_fn
<PowBackward0>              ← 这一步做的是"平方"
```

每一步都留了一个记号，说明"我是怎么做出来的"。

把记号串起来，就是一张**来路表**：

```
w ──(乘 x)──> pred ──(减 y)──> e ──(平方)──> loss
```

从头到尾，loss 知道自己是怎么从 w 一步步变出来的。

> 注意 `w.grad_fn` 是 `None`。因为 w 是**起点**，不是被算出来的 ——
> 这种自己就是源头的 tensor 叫**叶子**（leaf）。
> 只有叶子才会被存下梯度，因为只有它才是"我们要调的那个数"。

### 关键的一句话

**没有这张来路表，就没有自动求梯度。**

因为"往回倒推每步的斜率"这件事，必须知道路上经过了哪几步。
我们第 1 单元能推出公式，是因为我们**自己知道**路是怎么走的。

`requires_grad=True` 做的事，就是让 Tensor 把这条路自己记下来。

## 第 2 章 · 用 Tensor 把那 4 行重写一遍

现在看 `pytorch_regression.py`。还是第 1 单元那个例子：一个点 `(x=2, y=6)`，一个参数 w，真相是 w = 3。

```python
for step in range(STEPS):
    y_pred = w * x                 # 1. 前向：用当前的 w 算出预测值
    loss = (y_pred - y) ** 2       # 2. 算 loss：这次错了多重
    loss.backward()                # 3. 算梯度
    with torch.no_grad():          # 4. 更新参数
        w -= LR * w.grad
    w.grad.zero_()                 # 5. 把梯度清掉
```

跟第 1 单元对比一下：

| | 第 1 单元 | 这里 |
|---|---|---|
| 算预测 | `predict(w, x)` | `w * x` |
| 算 loss | `error ** 2` | `(y_pred - y) ** 2` |
| **算梯度** | **`2 * error * x`** ← 我们自己推的公式 | **`loss.backward()`** |
| 更新参数 | `w = w - LR * g` | `w -= LR * w.grad` |

**只有第 3 行换了。**

### 先验一下：它算对了吗

跑第一步，`backward()` 之后 `w.grad` 是 `-24.0`。

第 1 单元第 6 章我们推出来的公式：

```
w 的斜率 = 2 × (预测 − 真实) × x
        = 2 × (0 − 6) × 2
        = −24          ✓
```

**一模一样。**

这就是这个单元的第一个"啊哈"：`backward()` 不是魔法，它算出来的就是我们手推的那个数。

### 还有两行要多说

第 4 行的 `with torch.no_grad():` —— 这是在说"**接下来的计算不要记账**"。

因为更新参数（`w -= ...`）本身也是一次计算。如果让它记账，w 的来路表就会越接越长（w 由 w 算出来，w 又由 w 算出来……），而我们要的只是**改掉这个数**，不是记录一次新的运算。

第 5 行是这单元唯一真正的新知识，下一章单独讲。

---

## 第 3 章 · backward() 到底做了什么

### 把"往回倒推"摊开看

还是那个例子 `loss = (w·x − y)²`。设当前的误差 `e = w·x − y`。

我们想知道：**w 挪一点点，loss 变多少？**

跟第 1 单元第 5 章一样的初中代数。w 挪 δ：

```
e 变成  e + δ·x          ← w 每多 1，预测就多 x，误差也就多 x
loss 变成 (e + δ·x)²
        = e² + 2ex·δ + x²δ²
          ↑     ↑        ↑
       原来的  主要项   δ 很小，可忽略
```

所以：

```
loss 对 w 的斜率 = 2·e·x
```

**现在换个角度看这个结果。** 那两步是分开来的：

| 这一步 | 斜率是多少 |
|---|---|
| `e` 挪一点，`loss` 变多少（`loss = e²`） | `2e` |
| `w` 挪一点，`e` 变多少（`e = w·x − y`，其中 x 是常数） | `x` |
| 合起来：`w` 挪一点，`loss` 变多少 | **`2e × x`** |

**两个斜率相乘。** 这就是链式法则 —— 名字听着吓人，做的事就是"把路上每一步的斜率乘起来"。

### backward() 干的就是这件事

它拿着第 1 章那张来路表，**从 loss 那端往回走**：

```
loss ──(平方，斜率 2e)──> e ──(减 y，斜率 1)──> pred ──(乘 x，斜率 x)──> w
                                                                        ↓
                                                            一路上斜率乘起来 = 2e·x
```

`backward` 这个词就是"**往回**"的意思。往回走的过程叫**反向传播**。

> 所以它一点都不神秘：**把我们手推的过程，按部就班地做了一遍。**
> 我们靠纸笔，它靠那张来路表。

### 为什么值得这么做

因为**我们的公式只能用在一条直线上**。

第 1 单元那两个公式（`2×平均(误差×x)` 和 `2×平均(误差)`）是我们针对 `y = w·x + b` 专门推的。换成 `y = w₁x + w₂x² + b`，我们就得重新推一遍，还得再推一遍、再推一遍。

而 `backward()` **不需要你重新推**。它只看来路表 —— 路怎么走的，它就怎么倒着乘回去。你搭什么模型，它就求什么梯度。

## 第 4 章 · 必须写的那一行

这是这个单元**唯一一个第 1 单元没有对应物**的知识点。值得单独一章。

### backward() 是"加"，不是"写"

看这个实验：

```python
for i in range(3):
    loss = ((w * x) - y) ** 2     # 每次都重新算一遍前向
    loss.backward()
    print(w.grad)
```

```
第 1 次 backward 之后   w.grad = -24.00
第 2 次 backward 之后   w.grad = -48.00     ← 不是 -24
第 3 次 backward 之后   w.grad = -72.00
```

**它没有覆盖，它累加了。** `loss.backward()` 里做的事是 `w.grad += 这一步的梯度`。

### 所以不清零会怎样

`zero_grad_demo.py` 跑了同一个循环两遍，唯一的区别是有没有清零：

```
【每轮清零】
  step   更新前 w    本步真实梯度    .grad 里是     更新后 w
     1    0.0000      -24.0000      -24.0000       1.2000
     2    1.2000      -14.4000      -14.4000       1.9200
     3    1.9200       -8.6400       -8.6400       2.3520
     4    2.3520       -5.1840       -5.1840       2.6112
     5    2.6112       -3.1104       -3.1104       2.7667      ← 稳稳逼近 3

【忘记清零】
  step   更新前 w    本步真实梯度    .grad 里是     更新后 w
     1    0.0000      -24.0000      -24.0000       1.2000
     2    1.2000      -14.4000      -38.4000       3.1200      ← 多了旧账
     3    3.1200        0.9600      -37.4400       4.9920      ← 多了旧账
     4    4.9920       15.9360      -21.5040       6.0672      ← 冲过答案了
     5    6.0672       24.5376        3.0336       5.9155
```

第 2 步，本步真正的梯度是 `-14.4`，但 `.grad` 里是 `-38.4` —— 它把第 1 步的 `-24` 也背上了。

**步子里混进了历史。** 参数一路冲过正确答案 3，跑到 6 才回头。

### 为什么 PyTorch 不帮你清

因为累加**不是 bug，是设计**。

有一个很有用的场景：数据太多，一次算不完，想分两批算梯度再加起来 —— 这时候累加正是你要的。（数学上说得通：一批的梯度加上另一批的梯度，正好是合起来那批的梯度。）

但对最普通的训练循环来说，**上一轮的梯度是过期的情报**：参数都挪过了，那个数早就不算数了。

PyTorch 不知道你是哪种情况，所以它不替你决定。**你必须自己写。**

```python
optimizer.zero_grad()
```

## 第 5 章 · 两个参数：这里什么都不用改

第 1 单元里，把 b 加回来的时候我们做了额外的工作 —— 单独推了一遍 b 的斜率，还解释了半天"为什么 b 那里没有 `× x`"。

这里试试：

```python
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)

loss = (w * x + b - y) ** 2
loss.backward()

print(w.grad, b.grad)
```

```
w.grad = -24.0     ← 2 × (0−6) × 2
b.grad = -12.0     ← 2 × (0−6)，没有 x
```

**两个梯度都出来了，而且都对。** 我们一行推导都没写。

### 为什么 b 那里自动就没有 x

回去看第 3 章那张表。b 的来路是**加法**：

```
w ──(乘 x)──> ┐
              ├──(加)──> pred ──(减 y)──> e ──(平方)──> loss
b ───────────>┘
```

加法那一步的斜率是什么？**1**。因为 b 挪一点点，pred 就挪一模一样多。

```
b 的梯度 = 2e × 1 = 2e
```

而 w 那一步的斜率是 `x`，所以 `w 的梯度 = 2e × x`。

**第 1 单元里需要解释半天的那个区别，在这里只是"路上那一步做的是什么运算"。**

`× x` 不是凭空冒出来的，也不是需要背的规则 —— 它来自"w 先乘了 x 才变成预测值"。

### 再多几个参数也一样

100 万个参数就是 100 万条来路，`backward()` 照样倒着走一遍，各自填各自的 `.grad`。

第 1 单元里每加一个参数就要重推一遍公式的日子，结束了。

## 第 6 章 · nn.Module：把参数装进一个盒子

### 先说说手写版哪里不顺手

用裸 Tensor 写下去，事情会越来越啰嗦：

- 每个参数都要记得写 `requires_grad=True`
- 每个参数都要记得手工更新、手工清零
- 参数一多，"更新每个参数"这句话就得靠人肉一个个写

而且**没有一个地方能回答"这个模型有哪些参数"**。优化器想帮忙都无从下手。

### nn.Module 就是来回答这个问题的

```python
class Line(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(1, 1)     # 1 个输入，1 个输出

    def forward(self, x):
        return self.linear(x)             # 盒子里做的就是 w·x + b
```

两个部件：

- **`forward`** —— 告诉盒子"给我一批 x，怎么算出预测"。就是我们手写的 `predict`。
- **`nn.Linear(1, 1)`** —— 一个现成的零件，里面已经装着一个 w 和一个 b。

里面真的有两个参数：

```
weight   shape=(1, 1)  requires_grad=True   值=+0.764539
bias     shape=(1,)    requires_grad=True   值=+0.830008
一共 2 个参数
```

注意 `requires_grad=True` 已经替你写好了。零件的参数本来就是拿来训的。

### 关键的一步：parameters()

```python
model.parameters()
```

**它把所有参数打包成一个可以遍历的东西。** 看着不起眼，但它才是 `nn.Module` 真正值钱的地方 ——

有了它，"对每个参数做同一件事"第一次变成了一句能写出来的话：

```python
for p in model.parameters():
    p -= lr * p.grad
```

这就是下一章优化器要做的事。**没有 `parameters()`，就没有通用优化器。**

### 两个小提醒

**一、`nn.Linear` 的初始值是随机的**，不是 0。第 1 单元我们从 0 出发，这里要写上 `torch.manual_seed(42)` 才能让每次跑的结果一样。想跟第 1 单元严格对齐，也可以自己把它清零。

**二、输入形状。** `nn.Linear` 要的是"一批样本"，形状是 `(样本数, 特征数)`。所以 25 个点要竖过来：

```python
x = torch.tensor(X).reshape(-1, 1)     # (25,) -> (25, 1)
```

`-1` 的意思是"这一维你自己算"。

## 第 7 章 · optimizer.step()：把那一行打包

第 1 单元里，更新参数是这一行：

```python
w = w - LR * dw
b = b - LR * db
```

两个参数就得写两行。100 万个参数呢？

优化器做的事就是把它变成一句：

```python
optimizer = torch.optim.SGD(model.parameters(), lr=LR)
...
optimizer.step()          # 对所有参数，各做一次 p -= lr * p.grad
```

拆开看，`step()` 里的内容和第 1 单元**一字不差**：

```python
for p in model.parameters():
    p -= lr * p.grad
```

`SGD` 这个词就是"随机梯度下降"（Stochastic Gradient Descent）。这里数据是全部一起算的，所以其实是普通梯度下降，名字先不用管。

### 同样打包的还有清零

```python
optimizer.zero_grad()
```

等于：

```python
for p in model.parameters():
    p.grad = None
```

**优化器需要 `parameters()`，就是为了这两件事。** 它得知道"所有参数"是哪些，才能一个个地清零、一个个地更新。

### 所以三样东西的分工是

| 谁 | 管什么 |
|---|---|
| `nn.Module` | 参数放在哪、怎么算预测 |
| `loss` 函数 | 怎么衡量"错得多重" |
| `optimizer` | 拿到梯度之后，怎么改参数 |

`backward()` 不归它们任何一个管 —— 它是 Tensor 自己账本上的功能。**这也是为什么 `loss.backward()` 是写在 loss 上的，而不是写在 optimizer 上的。**

---

## 第 8 章 · 串起来：PyTorch 的五步循环

```python
for step in range(STEPS):
    optimizer.zero_grad()              # 1. 清掉上一轮留下的梯度
    y_pred = model(x)                  # 2. 前向：算出预测
    loss = criterion(y_pred, y)        # 3. 算 loss：这次错了多重
    loss.backward()                    # 4. 算梯度：每个参数各自的斜率
    optimizer.step()                   # 5. 往反方向挪一小步
```

和第 1 单元那张表一一对照：

| 第 1 单元（手写） | 这里 | 谁在做 |
|---|---|---|
| —（不存在） | `optimizer.zero_grad()` | 优化器 |
| `predict(w, b)` | `model(x)` | `nn.Module` |
| `loss(w, b)` | `criterion(y_pred, y)` | loss 函数 |
| **`gradient(w, b)`** | **`loss.backward()`** | **Tensor 的账本** |
| `w -= LR * dw` | `optimizer.step()` | 优化器 |

第 4 步是唯一一行"本来由我们推公式完成"的工作，现在交出去了。

### 验证一下：真的完全一样吗

`handwritten_vs_pytorch.py` 把两边并排跑：同一份 25 个点、同一个起点 `w=0, b=0`、同一个学习率、同样 150 步。

```
                        w                 b              loss
手写公式      2.003602481184    1.029341821244    0.010371660634
PyTorch       2.003602481184    1.029341821244    0.010371660634
相差                 0.00e+00          0.00e+00
```

**小数点后十位完全一样，一位不差。**

这不是"差不多"，也不是"效果接近"。这是同一件事的两种写法：

> `backward()` 算出来的，就是我们手推的那个公式。
> 它只是**不用你推**而已。

这也正是这个单元要你带走的一句话：

**PyTorch 自动帮你做的，是"推导 + 计算"。它没有帮你做任何你想不到的事。**

## 第 10 章 · 练习

改代码之前，**先猜结果，再跑**。

1. 在 `pytorch_regression.py` 里，把 `w.grad.zero_()` 删掉，跑一遍。
   w 最后是多少？（原来是从 0 出发、12 步走到 2.9935 的。）为什么变这样？

2. 把 `w.grad.zero_()` 从循环**末尾**挪到**最上面**（`backward()` 之前），跑一下。
   它会报错。报的是什么错？
   （提示：第一次进循环时，`w.grad` 是什么？再想想 `optimizer.zero_grad()`
   为什么不会报这个错。）

3. 在 `pytorch_regression.py` 里，把 `with torch.no_grad():` 那一行去掉。
   跑一下看报什么错，再想想它为什么不让这么干。

4. 在 `pytorch_regression_full.py` 里，把 `optimizer.zero_grad()` 注释掉，跑一遍。
   结果跟 `zero_grad_demo.py` 里那组"忘记清零"的现象对得上吗？

5. 把 `pytorch_regression_full.py` 的 `STEPS` 改成 20，loss 停在 0.0263 左右 —— 还没走完。
   改回 150 是 0.0104。**但这个数还能更低吗？**
   拿真相 `w=2, b=1` 直接算一遍 loss，是 0.0115 —— 比模型学到的**还高**。想想为什么。

6. 把 `nn.Linear(1, 1)` 换成两层：`nn.Sequential(nn.Linear(1, 3), nn.Linear(3, 1))`。
   **一行梯度公式都不用写**，直接跑。参数量从 2 变成 10，loss 几乎没变好（0.01036）。
   想想第 1 单元遇到这种模型会怎么样。

## 附录 · 再往下走

这个单元只碰了 PyTorch 最表面的一层。等你把上面的都弄明白了，下面这些是自然的下一步：

| 接下来 | 一句话 |
|---|---|
| **`DataLoader`** | 数据太多，一批一批喂。第 4 章那个"梯度累加"就是为它准备的 |
| **别的优化器** | `Adam`、`RMSprop`…… 换个名字就行，五步循环一个字不改 |
| **`model.to(device)`** | 搬到 GPU 上。Tensor 的账本跟着一起搬 |
| **`torch.save` / `load`** | 把训好的参数存下来 |
| **反向传播自己写一遍** | 不调 `backward()`，手动实现一遍链式法则 —— 那时你就真的懂它了 |

最后一条尤其推荐。等你亲手写过一次反向传播，回头看 `loss.backward()`，
会觉得它平常得像 `print()`。
